# CLAUDE.md: GoNetherlandTours

A fast, SEO-friendly Google Ads landing site for a GoTour brand (Netherlands; self drive, chauffeur, coach tours; US travellers; EUR prices). It captures enquiries reliably (quiz + forms), stores consent evidence and syncs leads to GoHighLevel. It is a **skeleton the team iterates on**. **Update this file whenever you change anything it describes.**

## Stack
Laravel 12 (PHP 8.2+; dev PHP 8.4), server-rendered Blade (no SPA), Tailwind v4 + Vite, Alpine.js (+ focus plugin), MySQL (utf8mb4; SQLite only for tests), custom admin (no Filament/WordPress). Fonts self-hosted: Playfair Display + Montserrat.

## Run it (XAMPP)
See `docs/reference/LOCAL_XAMPP.md`. Short: `.env` from `.env.example`, DB `gonetherlandtours`, `composer install`, `npm install`, `php artisan key:generate`, `php artisan migrate --seed`, `php artisan storage:link`, `npm run build` (or `npm run dev`), `php artisan serve`. Tests: `php artisan test`. Composer on this PC is old: use a fresh `composer.phar`.

## Business rules that are not obvious from code
- **Consent text is exact** (`config/gnt.php` > `consent_template`); `[Company Name]` = Admin > Settings legal company name. Required, unticked by default, enforced in browser AND server. The text shown, terms version (Terms page `version`), timestamp, IP, user agent and page URL are stored per enquiry. Do not reword without legal review.
- **Every form uses `<x-enquiry-form>` and `POST /enquiry`**: reCAPTCHA v2 checkbox (explicit render; **fails closed**), honeypot `company_website`, CSRF, rate limit 6/min/IP, sanitising, E.164 phone. A new form = another use of the component, never a new endpoint.
- **Country code**: custom flag listbox (`countrySelect` in app.js) over a native `<select name="country_code">`, which stays the submitted value and the no-JS control. To add a country: `config/gnt.php` + a flag SVG in `public/images/flags/`.
- **No-JS**: hero shows `.nojs-only` plain form. Never nest `<noscript>` (the form already contains one).
- **Tracking**: `CaptureTracking` middleware stores first touch (30-day encrypted cookie) + latest touch (session); both saved on the enquiry and sent to GHL as `(First)` / `(Last)` fields. Thank You page fires the `enquiry_thank_you` dataLayer event only after a real submission (session flash). GTM loads only when its ID is set.
- **GHL is OFF** unless a token + Location ID exist and the sync is ticked on. They are saved in Admin > GoHighLevel (`Admin/GhlController`, administrators only; token `Crypt`-encrypted in `settings`) with `.env` `GHL_API_TOKEN`/`GHL_LOCATION_ID` as fallback; read via `ghl_token()`/`ghl_location_id()`/`ghl_enabled()`; never in code/git. Fields are matched by exact name; names live ONLY in `GhlFields`. Sync never blocks an enquiry; status + contact ID are stored on the enquiry; retry in admin. Existing contacts keep their first-touch values.
- Form variants: `<x-enquiry-form variant="quiz|modal|default">` (see FORMS_AND_TRACKING.md). The pop-up (`modal`) requires budget and reads its dropdown options from quiz steps with keys `group_size`, `travel_style`, `nights`, `budget`: do not rename those keys. Quiz step key `travel_date` (type `date`, calendar picker; stored as YYYY-MM-DD, as on every form's travel date field) fills the enquiry's travel date.
- Quiz steps/options are database driven (Admin > Quiz). Step `key` = answer name = GHL field `Quiz: <Key>`; avoid renaming keys once leads exist.
- Sample packages (`is_sample`) are `noindex`, have no price (`[CONFIRM: price]`). Never invent business facts: use `[CONFIRM: ...]` and list it in `docs/reference/CONTENT_TO_CONFIRM.md`.
- Legal pages are starter templates, not legal advice.
- **Pages are dynamic (page builder).** Every page (Home, About, Contact, FAQ, Testimonials, Terms, Privacy and any page created in Admin > Pages) is an ordered list of **sections** stored in `pages.sections` (JSON). Section types, their admin fields, defaults and sanitising live in ONE place: `app/Support/Sections.php`; each type renders from `resources/views/sections/{type}.blade.php`; `pages/show.blade.php` loops them (`Admin\PageController` edits pages/sections, `PageController` renders). To add a section type: add it to `Sections::all()` + a view; the admin form is generated. `DefaultSections` holds the starting content that reproduces the original design (used by the `make_pages_dynamic` migration, which keeps text admins had edited, and by `PagesSeeder`). Built-in pages (`is_system`) keep fixed URLs (`Page::path()`) and cannot be deleted; custom pages live at `/{slug}` (reserved words in `Page::RESERVED`; drafts 404; in the sitemap when published and indexable). Hero sections own the page H1: keep exactly one H1 per page. Hero video: see below.
- **Navigation and site text are dynamic.** `menu_items` (Admin > Navigation, `NavigationController`, `MenuItem`): header items (`link`, `tours` = automatic tour-types mega menu, `cards` = dropdown of image cards whose children are the cards) and footer links. Button labels, top bar, mobile bar, pop-up, quiz title, thank-you and packages intro text are settings with defaults in `config/gnt.texts`, read with `text('key')` and edited in Admin > Settings (a saved blank hides the element). New label = add to `config/gnt.php` `texts` + `SettingsController::GROUPS`.
- Videos use `<x-video name="homepage_banner">` (`video_name` field in the `video_feature` section): drop `public/videos/{name}.mp4` to replace the poster placeholder. The hero PHOTO is the LCP image; the optional hero video is deferred (`initBgVideo()` in `app.js` loads it after page load on 768px+ only): never make it autoplay in the HTML. Static images >60KB need a `name-800.webp` copy for `<x-picture>` srcset; see SEO_CHECKLIST.md "Lighthouse results". Images uploaded in the page builder are processed by `ImageService` (WebP, 480/960/1600).
- Images: only free-for-commercial-use; credit in `IMAGE_CREDITS.md`. Currently all images are generated placeholders.
- Blog: `blog_posts` table, `BlogPost` model, admin at Admin > Blog (`Admin\BlogController`, editors allowed), public `/blog` and `/blog/{slug}` (`BlogController`, JSON-LD `BlogPosting`, in sitemap). Visible = `is_published` and `published_at` not in the future; publishing with no date sets today. The home "Guides and inspiration" section shows the 2 newest (`partials/blog-card`) and hides if there are none. `BlogSeeder` seeds two placeholder posts.
- Motion (home + blog cards): scroll reveal via `data-reveal="up|left|right|zoom"` + optional `style="--d:120ms"` (CSS in `app.css`, `initReveal()` in `app.js`; hidden only when `.js`, skipped for reduced motion, attribute removed after the reveal so hover transitions return). Hero uses CSS `.hero-in`; `.float-slow` and `.kenburns` are ambient loops. Do not put `data-reveal` on elements toggled by `x-show` (e.g. package tab cards).
- Headings (`x-section-heading`, home H1, gallery title) support `*word*` for an italic accent word via `emphasize()` in `app/helpers.php` (escaped first, so safe). Home "Journeys by traveller" is an expanding-panel strip from `lg` (`.expand-strip`/`.strip-panel` in `app.css`); the gallery tiles pop out on hover (`.gallery-tile`, pointer devices only).
- Gallery, team, testimonials and the rest of the former Home/About design are now sections (see above); the gallery is the `gallery` section (6/12/18 photos for a gap-free grid, clicking a photo opens the viewer).
- Package search by location: the `/packages` type/destination filter is unchanged; a "Search by location" link opens a popup (Alpine `locationSearch` in `resources/js/app.js`) that fetches an HTML fragment from `GET /packages/search?q=` (`PackageController::search`, view `partials/package-search-results`, matches destination name, title or summary, LIKE with wildcards escaped, max 12) with no page reload.
- Page list (client site map): Home, Destinations (`/destinations/{slug}`), Self Drive / Chauffeur / Coach (`/tours/{slug}`, `TourTypeController`, copy + SEO editable in Admin > Tour types; the `/packages?type=` filter stays and canonicals to `/packages`), Package details, About (+ Meet the team section placeholders), Contact, Privacy, Terms, FAQ (`/faq`), Blog, Testimonials (`/testimonials`), plus the "Search by location" popup. FAQ/Testimonials read Admin > FAQs / Testimonials. All are in `sitemap.xml` and the menus/footer.
- **Safety and speed rules.** Rich text is sanitised by `App\Support\HtmlSanitizer` (DOM allow-list; `clean_html()` calls it): never echo admin HTML without it, and never relax it to regexes (encoded `javascript:` links got through the old one). Shared per-request data (tour types, destinations, quiz steps) comes from `App\Support\SiteData` (memoised, flushed each request): use it instead of re-querying in views, and eager-load `destination`/`tourType`/`images` on package lists. `HardeningTest` enforces a per-page query budget, security headers and the friendly error pages (`errors/419,429,500,503`; 500/503 are self-contained so they work if the database is down). CSP currently only sets safe directives (frame-ancestors, base-uri, object-src, form-action); a full script policy would have to allow Alpine, GTM and reCAPTCHA. CI (`.github/workflows/tests.yml`) runs the suite on pull requests and gates both deploy workflows. Saving a photo with no alt text shows a warning in the page builder.
- **Design refresh rules.** The hero is a responsive PHOTO (`hero-home.webp` + `-800` copy, `<x-picture priority>` + a preload with `imagesrcset`); the background video, if `public/videos/homepage_banner.mp4` exists, plays over it on 768px+ only. The header floats transparent over pages whose first section is a photo hero (`hero_video_quiz`, `hero_seasons`) and package pages: `PageController`/`PackageController` pass `overlayHeader`, `partials/header` adds `.hdr-overlay` and Alpine toggles `.is-solid` on scroll or when a menu opens; the white-text rules are UNLAYERED CSS at the end of `app.css` on purpose (utilities like `text-ink` would otherwise win). The top bar is hidden on phones (the bottom action bar has Call + Quote). Featured packages are a scroll-snap carousel (Alpine `carousel` must be registered BEFORE `Alpine.start()` in `app.js`; the track needs `relative` or `sr-only` text inside cards escapes the clip and causes sideways scrolling). Package cards stack image-on-top at every size. Below-the-fold sections use `content-visibility: auto` (`main > :nth-child(n+4)`) to cut start-up cost; `body` has `overflow-x: clip`. Section styles: `steps` = timeline|cards, `testimonials` = dark|light|spotlight. Package itinerary days can show one of the package's own gallery photos. `/destinations` lists destinations (texts in Settings). Text links need a 44px touch area (`inline-flex min-h-[2.75rem]`).
- **Trust settings.** Admin > Settings > Trust and reassurance (`quiz_rating_label`, `quiz_trust_1..3`, `quote_promise`, `reviews_badge`): blank hides each one; shown in `components/quiz` (rating + reassurances + promise), `sections/cta_banner` (promise) and `sections/testimonials` (rating line). Contact page gets a "What happens next" `steps` section (`DefaultSections::contactSteps()`).
- **Header & Footer snippets** (Admin > Header & Footer, administrators only: `SnippetController`, `CodeSnippet`, table `code_snippets`): custom code with name, code, placement (`head`, `body_start`, `body_end`), scope (all, or only chosen paths) with optional excluded paths (`/blog/*` wildcards), order and on/off. `layouts/app.blade.php` outputs them with `snippets($position)` exactly as entered (raw, no sanitising); the active list is cached under `code_snippets.active` and flushed on save. Admin pages are not affected; a site without the migration simply shows none.
- **Partner logos** (`sections/partners.blade.php`, Alpine `partnerSlider` in `app.js`, `.pslider*` in `app.css`): 3 logos visible (2 tablet, 1 phone), slides by ONE logo in a loop: slow 1.8s eased move + 0.3s pause, logos fade out/in as they leave/arrive, looping by repeating the first 3 logos at the end then snapping back; pauses on hover/focus/hidden tab; reduced motion = no movement, logos wrap. Logos are managed in Admin > Pages > Partner logos.
- **Mega menus** (`partials/header.blade.php` + `partials/mega-cards.blade.php` + `partials/mega-bar.blade.php`), styled after gorailtravel.com: full-width navy panels. Tour Types = ways to travel (tour types) + featured trips + one featured trip card; Destinations (automatic when a header link goes to /destinations) and any `cards` item (About Us) = a row of photo cards; each has a bottom bar (tagline + buttons). Wording: Admin > Settings > Top bar and header (`mega_*` keys).
- **Logo** (`partials/logo.blade.php`): new SVG artwork `public/images/logo-gonetherland.svg` (full color) and `logo-gonetherland-dark.svg` (white windmill/wordmark, orange tulips and "Netherland", colored flag). Header base state (transparent over a photo hero) = DARK-BACKGROUND logo; sticky/solid state (scrolled, menu open, pages without a photo hero) = FULL-COLOR logo, swapped by CSS (`.hdr-logo .logo-color/.logo-white`); footer (dark) = dark-background logo. A logo uploaded in Admin > Settings overrides all of it. JSON-LD logo = `logo-gonetherland.png`. Favicons (`favicon.ico`, `images/favicon-*.png`, `apple-touch-icon.png`) are the windmill + tulips icon only. Old `GoNetherlandTours-*.webp` files are no longer used.
- **About page layout** follows the reference (dreamtripsscotland.com/about-us): `hero_video_quiz` (photo + quiz), `feature_cards` style `strip` (slim navy strip), two `text_image` sections (photo left/right, optional highlighted line + button), `why_band` with a side photo, `blog_latest` (3 columns when 3+ posts, optional intro), team, `testimonials` dark, `steps` style `tiles` (dark numbered tiles, optional intro + button) and `cta_banner`. Defaults live in `DefaultSections::about()`; migration `about_page_reference_layout` swaps the page only if it is still on an earlier default layout.
- **Fonts and layout shift.** The layout preloads the Montserrat WOFF2 (`Vite::asset` of the Fontsource file) so text is laid out once; without it the package hero re-wrapped when the font arrived (CLS 0.18). Do not preload more fonts without re-checking home LCP (the hero photo competes for bandwidth). Reserve space for text that can wrap on phones (see the travel-style line in `package-show`).
- **US English.** The site targets US travelers, so visitor-facing copy uses US spelling (traveler, color, favorite, center) and "inquiry" in plain text (identifiers, admin screens, staff emails, CRM form names and the legal consent text keep "enquiry"). `App\Support\UsSpelling` converts text (HTML-aware: never attributes or links); the `usp_wording_us_spelling_and_style_notes` migration applied it to stored content; `SpellingGuardTest` fails if UK spellings appear in views, JS, config, seeders or default sections. Selling points: wording lives in Settings (`usp_*`, `partials/why-us`) and the `usp_proof` section; only coach tours are "small group", self drive and chauffeur are private (`tour_types.style_note`).
- Admin roles: `admin_users.role` = `admin` (full) or `editor` (content only: dashboard, enquiries, packages, tour types, destinations, pages, FAQs, testimonials, blog, media). Enforced in `AdminAuthenticate` by route-name prefix (`AdminUser::EDITOR_AREAS`); a new admin area is administrators-only unless added there. Cannot demote self or the last admin.
- Admin: separate `admin` guard + `admin_users`; login throttled 5/min; cannot delete self or last admin. Admin first user comes from `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD`.
- `SITE_NOINDEX=true` (preview/staging only) forces noindex meta, `X-Robots-Tag` and `Disallow: /` robots.txt. Must be false on the live site. See `docs/reference/SHARING_PREVIEW.md`.
- Package routes bind by **slug** (`/admin/packages/{slug}/edit`).

## Conventions
Blade + small Alpine; no inline business logic in views beyond display. Colours/fonts only via tokens in `app.css`. Rich text is sanitised with `clean_html()`. Settings via `setting('key')` (cached; `Setting::put` clears cache). New setting = add to `SettingsSeeder` and `SettingsController::GROUPS`.

## Gotchas
- PowerShell 5.1 `Set-Content -Encoding utf8` adds a BOM that breaks `.env`, JSON and PHP files: write files with the editor tools or `[IO.File]::WriteAllText` with `UTF8Encoding($false)`.
- `public/robots.txt` must not exist (the route generates it); likewise no `public/sitemap.xml`.
- `in:` validation rule splits on commas: use `Rule::in()` for values containing commas.
- Tests call `Http::preventStrayRequests()` (tests/TestCase.php) and blank GHL env in `phpunit.xml`: tests must never reach the live CRM.
- reCAPTCHA keys in `.env.example` are Google's TEST keys.
- Production queue on Hostinger shared hosting runs via cron `schedule:run` (see DEPLOYMENT.md).

## Uploads and deploys
- `storage/app/public/*` (admin and developer uploads) is git-ignored, so a push never carries it. After adding or changing uploaded images locally, run `npm run sync:media` (add `-- --dry-run` to preview, `-- --target=staging` for staging). It copies the folder to the server over SSH using the host details in `.deploy.env` (git-ignored; template in `.deploy.env.example`).
- Database rows that point at uploads (e.g. `tour_types.image`) must travel as a migration, not a local edit, or the server keeps the old path.
